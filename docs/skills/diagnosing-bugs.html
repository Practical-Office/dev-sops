Diagnosing bugs

Six-phase Diagnosis Loop that turns a confirmed bug into root cause and a regression-ready fix path.

Why

Reproducibility before patches

Guess-and-patch creates regressions. The Diagnosis Loop forces a deterministic feedback command, a minimized reproduce, ranked hypotheses, and one-variable instrumentation before the fix.

When

Use this skill

  • Triage State is ready-for-agent or ready-for-human
  • Bug report template is complete (or grilled to completion)
  • You are about to change production code for a defect

Skip only for trivial typos with an obvious red test — still run a minimal reproduce.

How

Six phases

  1. Feedback loop — one red-capable, deterministic command
  2. Reproduce + minimise — shrink until every step is load-bearing
  3. Hypothesise — 3–5 ranked, falsifiable hypotheses
  4. Instrument — one variable at a time; tagged probes
  5. Fix + regression test — hand off to /tdd
  6. Cleanup + post-mortem — green loop, remove debug harnesses, ticket RCA notes

Inputs / outputs

InputsOutputs
Complete bug ticket; triage labels; environment detailsRoot cause; diagnosis notes; red test; fix path for /tdd

Anti-patterns

What to avoid

  • Fixing before a reliable red signal
  • Skipping minimise — debugging the whole system at once
  • Jumping to /implement or a bare PR without diagnosis notes

Micro-scenario

Abstract example

A ticket reports checkout fails on Safari only. Triage sets ready-for-agent. The agent runs /diagnosing-bugs, finds a deterministic Playwright repro, minimises to one API call, ranks three hypotheses, instruments the response parser, confirms a date-format mismatch, and hands off to /tdd with a failing unit test at the parser seam.
